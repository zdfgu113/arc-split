Contract requirements:
- Native USDC on Arc uses 18 decimal units. ERC-20 USDC uses 6 but this application must use native value only.
- Atomic payouts to 2-10 distinct nonzero recipients, positive amounts, exact sum equals msg.value.
- No owner, platform fee, upgrade, sweeping, custody, or withdrawal functionality.
- Per-payer bytes32 payment reference prevents a duplicate payment. Mark it used before any external call. A failing receiver must revert every payout and restore the reference as unused.
- A public event records payer, reference, total, recipient and amount arrays, and a note of at most 96 UTF-8 bytes.
- Compile to a conservative EVM target (Paris) for interoperability. Test successful 70/30 transfers, recipient failure atomicity, duplicate references, wrong totals, invalid/duplicate recipients and oversized notes. State that standard EVM tests do not establish Arc-specific behavior.

- Amount input supports at most 6 decimal places. Use integer math: convert total to micro-USDC, percentages to basis points, assign remainder by largest fraction with stable ties, and then multiply micro-USDC by 10^12 for native calls. Exact conservation is mandatory; reject any zero payout.
- Add/remove 2-10 members, editable nicknames and addresses, fractions sum exactly to 100%, live calculation, downloadable CSV, explicit confirmation before wallet request.

- Record only browser-local demo or verified receipts; demo records must stay labelled as demo.
